# 《道德经》文献存档：存储设计

## 范围

以三种出土本（六个版本）为主，另收传世的王弼本和后人校订的本子：

| 版本 id | 内容 | 性质（`kind`） |
|---|---|---|
| `guodian-jia` / `guodian-yi` / `guodian-bing` | 郭店楚简《老子》甲、乙、丙组 | 出土本 |
| `mawangdui-jia` / `mawangdui-yi` | 马王堆帛书《老子》甲本、乙本 | 出土本 |
| `beida` | 北京大学藏西汉竹书《老子》 | 出土本 |
| `wangbi` | 王弼本《老子》（释文取自 tt24h 实录） | 传世本 |
| `jiaoding` | 校订本（tt24h 整理者对照各本断句校订） | 校订本 |

材料的性质登记在 `witnesses.yaml` 的 `kind` 里：出土本是一手材料（`excavated`，没写按它算），拓印与石刻是二手（`rubbing`），传世本（`transmitted`）与后人校订整理的本子（`edition`）也是史料。论文和他人编纂的对照资料同样可以收录，在来源记录里写 `study: true`；目前有 tt24h 的《四种原文表》。

其他传世本（敦煌写卷、河上公、傅奕等）、拓本和《庄子》《韩非子》里的引文还没收，之后可以按同样的结构追加。

## 三条原则

1. **来源决定写法**：`text` 字段完全照抄来源的释文，包括它用的通假字、隶定字形和符号，不做任何转换。需要统一的地方只在查询时处理，不改存档。
2. **每一条都能追溯**：每个文本单位都指向一份已登记哈希的原始抓取文件。任何人都能核对"这一行是从哪个文件的哪个位置来的"。
3. **拿不准就写空**：版本的简数、出版信息等拿不准的字段写 `null`，每条事实都标明依据，不靠记忆补全。

## 目录

```
data/
  witnesses.yaml        版本登记表（各版本的基本信息，每条事实标明依据）
  sources/<id>.yaml     来源记录：出版物或网站、授权状态、抓取日期、原始文件哈希
  raw/<source>/         抓取到的原始文件，原样保存，不修改
  images/<来源>/        简帛影像，原样保存（从扫描本抽出的内嵌 JPEG 字节不改动）
  plates/<版本>.jsonl   影像登记：每张图来自哪个来源的哪一页、对应哪些文本单位
  witnesses/<版本>.jsonl 文本单位，每行一枚简或帛书一行（来源只按章给出时每行一章），按阅读顺序
  alignment/            逐章对读表与逐行释文（tt24h 整理），见下一节
schema/                 上述各类数据的 JSON Schema
scripts/validate_data.py 校验脚本
scripts/import_wikisource.py 把维基文库原始页面切分成文本单位（郭店、马王堆）
scripts/import_tt24h.py  把 tt24h/daodejing（CC0）的北大汉简实录按简切分
scripts/import_alignment.py 把 tt24h 的排版数据与实录对上，生成 alignment/ 以及王弼本、校订本的文本单位
scripts/alignment.py    对读表的解析、拼回与核对（import_alignment.py 与 validate_data.py 共用）
scripts/extract_plates.py 从扫描本 PDF 抽出图版页，并按页上印的简号、行号挂到文本单位
tests/                  脚本与展示站的测试（用占位字符，不含任何真实释文）
```

## 文本单位记录的字段

详细定义在 `schema/unit.schema.json`，要点：

- `id`：`<版本>.<三位序号>`，序号在版本内连续，一旦分配不再改动，别处用它来引用。
- `unit_no`：来源给出的简号或行号，原样记录。
- `text`：释文，原样。
- `marks`：来源中的符号（章节标记、重文号、合文号、句读等）及其位置。符号同时仍在 `text` 里。
- `damage`：残缺、模糊、补字的区间，并写明补字者。
- `notes`：来源附带的注释，保留作者，不改写。
- `source_ref`：来源 id、原始文件路径、文件内位置。
- `status`：`unverified`（只核对过一个来源）或 `double-checked`（已与第二个独立来源逐字核对）。

## 对读表与逐行释文（`data/alignment/`）

来自 tt24h/daodejing（CC0）。对读表按王弼本分 81 章，同一章里各版本的格子同列对齐，同一列就是同一处；逐行释文是各底本照简、照行的原文，每个字指向对读表里的一格。

```
alignment/
  versions.json         对读表里的各行（版本）：id、tt24h 的版本标记、行首简称、实录文件、底本、参照书、实录一行的性质
  chapters/NNN.json     一章的对读表：每个版本一行格子（郭店六十四章分成几段），另有尾注
  lines/<版本>.jsonl    各简、各行的实录：{no 简号或行号, text 原文, refs 每个字对应的 [章, [列…]]}
  equivalents.json      共用通行字的判定规则：含这些字的列不判定、视作空的字、视同相等的字
  glyphs.json           〚…〛造字序列与补充字体 DaoDeJingExt 码位的对应
  study.json            tt24h 的概述、凡例与参考书目
```

一格写成 `""`（空）、字符串（只有正文）或对象，对象的键为：`t` 正文、`f` 标记（残、衍、脱、补、占）、`r` 通行字、`c` 正确字（讹字的纠正）、`n` 尾注框、`l` 简号或行号、`p` 断句标点（只有校订本有）；没有的键不写。实录里 `〚F字〛` 是残字，`〚⿰…〛` 一类是造字序列，其余是普通的字。各键的含义见 `scripts/alignment.py` 开头的说明。

这些文件都由 `scripts/import_alignment.py` 从 `raw/tt24h-daodejing/` 生成，不手改：脚本把排版数据按底本顺序拼回去，逐字对上实录，对不上就报错、不写任何文件；`--check` 核对已有的文件与重新生成的结果逐字相同。王弼本、校订本的文本单位（`witnesses/wangbi.jsonl`、`witnesses/jiaoding.jsonl`）也由它生成，每章一条；校订本的 `text` 是把一章的格子连起来、加上整理者断句的结果。

## 入库的规则

校验脚本会强制执行，不通过就不能提交：

- 来源的授权状态不能是 `unknown`，确认授权之后才能把文本放进仓库。
- 原始文件的哈希必须和登记的一致，文件被改动会被发现。
- 编号必须连续，残缺区间不能超出文本长度。
- 对读表里的版本都要是登记过的版本；逐章文件名与章号相符，共 81 章，各行格数相同；逐行释文里每个记号指向的格正是这个字，每个存字的格恰好被一个记号指向，格上的简号或行号落在实录里该行的最后一个字上。

## 已定的事

- **授权**（2026-10-14 项目所有者决定）：《道德经》为公版作品，本仓库用于学术研究，释文全文入库；来源未标明授权条款的按可收录处理。各来源的 `license` 如实记录这一判断和来源自身的声明。
- **影像**（同日决定）：简帛图版和照片也入库，直接存在 git 里，每张图在来源记录中登记 SHA-256。整本扫描书不入库，只抽图版页。
- **收录的材料**（2026-10-15 项目所有者提出）：不只收“本”。出土本是一手材料，拓印是二手，传世本和后人校订的本子也是史料，论文和他人编纂的对照资料同样可以收纳。

## 还没定的事

1. **独立核对对读表**：现有的对读表是 tt24h 整理者的对齐，本仓库没有另找依据复核。哪些处的对齐有争议，需要有依据的底本才能判断，对照结果也要写明依据，不由我自己判断。
2. **交叉核对**：同一版本最好有两个独立来源的释文逐字核对，这样 `status` 才能升到 `double-checked`。
3. **马王堆两本的逐行文本单位**：逐行实录已在 `alignment/lines/`，`witnesses/` 里仍是按章的维基文库释文，还没有并入。
